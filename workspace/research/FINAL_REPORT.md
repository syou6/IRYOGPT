## 1. エグゼクティブサマリー

### 結論

**サロンボードのスクレイピングは技術的に十分実現可能。** 競合5社（DOUKI, SalonConnect, Beauty Merit, Salons Solution, coming-soon）が全てスクレイピングで運用しており、Recruit公式APIは2017年に廃止済み。SalonConnectは月額¥3,980で2,000+サロンにサービス提供中。

### 重要な発見

| 項目 | 発見内容 |
|------|----------|
| Recruit公式API | **存在しない**（2017年廃止、復活の見込みなし） |
| 競合の手法 | **全社スクレイピング**（SalonConnect自ら「スクレイピング」と明言） |
| Akamaiレベル | CDNのみの可能性大（Bot Manager Premierではない） |
| reCAPTCHA | Google reCAPTCHA v2（画像認証）、頻度は低め |
| 法的リスク | 利用規約違反（民事）あり。刑事リスクはサロン同意で低減 |
| minimo | 公開APIなし。B2Bパートナープログラムは非公開 |

## 2. サロンボードのセキュリティ構成

### 2.1 検出レイヤー

| レイヤー | 使用有無 | 詳細 |
|----------|----------|------|
| Akamai CDN | ✅ あり | TLS終端・キャッシュ（Bot Managerではない可能性大） |
| Akamai Bot Manager | ❓ 不明 | sensor_dataエンドポイント未確認。HPB表示ページはCDNのみか |
| reCAPTCHA v2 | ✅ あり | ログイン時・操作時に出現（SalonConnectのFAQで確認） |
| IP制限 | ⚠️ 可能性あり | 短時間大量アクセスでブロック |
| セッション管理 | ✅ あり | パスワード6ヶ月強制変更 |

### 2.2 日本のHPB/SB開発者の実績

2024年の日本人開発者ブログで、基本的なPlaywright/Selenium + ステルスプラグインでHPBのスクレイピングに成功した事例あり。Akamai Bot Managerが本格稼働していない可能性を示唆。

## 3. 競合他社の技術分析

### 3.1 DOUKI（¥5,000/月）

- **開発者**: 個人（整体サロン経営者が個人開発）
- **技術**: TypeScript + Turborepo モノレポ、OpenAPI + Orval
- **同期方式**: Pub/Sub トリガー（~7秒遅延）
- **特徴**: SalonBoard Master アプリ（WKWebView）でセッション取得
- **CAPTCHA対策**: 非公開

### 3.2 SalonConnect（¥3,980/月）

- **開発者**: 株式会社セレナーデ（7名）
- **インフラ**: さくらインターネット専用サーバー
- **同期方式**: スクレイピング（FAQ で明言）
- **CAPTCHA対策**: 「日々チューニング」（具体手法非公開）
- **規模**: 2,000+ サロン

### 3.3 共通パターン

- サロンのSB認証情報を預かってサーバーサイドスクレイピング
- 同期方向: 外部 → SB は可能。SB → 外部は制限あり
- CAPTCHAは「稀に出る」レベル（対策チューニングで頻度低減可能）

## 4. アンチボット回避技術の世界動向

### 4.1 ブラウザ自動化ツール（2026年ランキング）

| ツール | 検出回避力 | 特徴 | 推奨度 |
|--------|-----------|------|--------|
| **Patchright** | ★★★★★ | Playwright fork、Runtime.enable CDP漏洩修正済み | **最推奨** |
| **Camoufox** | ★★★★★ | Firefox改造版、一貫性のある指紋プロファイル | 高 |
| zendriver (現行) | ★★★★☆ | nodriver fork、CDP leak一部残存 | 現行で十分 |
| Playwright + stealth | ★★★☆☆ | puppeteer-extra-stealth は2026/2廃止 | 非推奨 |
| Selenium | ★★☆☆☆ | WebDriver検知容易 | 非推奨 |

### 4.2 TLS指紋偽装

| ツール | JA3/JA4偽装 | HTTP/2指紋 | Python対応 |
|--------|-------------|-----------|-----------|
| **curl_cffi** | ✅ Chrome/Safari/Edge | ✅ Akamai H2指紋 | ✅ pip install |
| CycleTLS | ✅ | ✅ | Go (Python wrapper) |
| 素のhttpx/requests | ❌ 即バレ | ❌ | - |

**学術論文の知見**: 2026年2月のarXiv論文で、JA4 TLS指紋のみでCatBoostモデルがAUC 0.998、精度98.6%でbot検出可能と実証。→ **素のPython HTTPクライアントは使用不可**。

### 4.3 プロキシ（日本向け）

| サービス | 種類 | 日本IP | 月額 | Akamai成功率 |
|----------|------|--------|------|-------------|
| **SOAX** | レジデンシャル/モバイル | ✅ docomo/SB/au指定可 | $90/5GB | 85-96% |
| **IPRoyal** | レジデンシャル PAYG | ✅ | $1.75/GB | 80-90% |
| Bright Data | レジデンシャル | ✅ | $500+/月 | 95%+ |
| データセンターIP | 固定IP | - | 安い | 10-20% |

**SBの場合**: 競合が専用サーバー（さくらインターネット）の固定IPで運用していることから、**データセンターIPでも動く可能性が高い**。プロキシは保険として準備。

### 4.4 CAPTCHA解決

| サービス | 対応 | コスト | 速度 |
|----------|------|--------|------|
| **NopeCHA** | reCAPTCHA v2/v3 | $0.011/1K | ブラウザ拡張 |
| CapSolver | reCAPTCHA全種 | $0.60/1K | API |
| 2Captcha | 全種 | $1.00/1K | API (遅い) |

**SBの場合**: SalonConnectのFAQで「稀に画像認証が出る」レベル。チューニングで出現頻度を下げ、出た場合のみ自動解決。

### 4.5 行動シミュレーション

| 技術 | 検出回避効果 | 実装難易度 |
|------|-------------|-----------|
| **Xvfb + PyAutoGUI** | ★★★★★ (JS検出不可能) | 高 |
| Bézier曲線マウス移動 | ★★★★☆ | 中 |
| キーストローク動態模倣 | ★★★☆☆ | 中 |
| ランダム遅延 | ★★★☆☆ | 低 |

### 4.6 Akamai Bot Manager対策（万が一SBが使用していた場合）

| 手法 | 有効性 | コスト |
|------|--------|--------|
| Cookie harvesting (ブラウザで_abck取得→curl_cffiで再利用) | ★★★★★ | 無料 |
| Hyper Solutions API (sensor_data生成) | ★★★★★ | 有料 |
| プロファイルウォーミング (2-3日かけてブラウザ履歴構築) | ★★★★☆ | 時間のみ |
| sensor_data自力生成 | ★★★☆☆ | OSSはv2止まり、v3は商用のみ |

## 5. 推奨技術スタック

### Phase 1: 最小構成（SB資格情報入手後すぐ）

```
zendriver (現行) + ステルスJS (現行)
  ↓ ログイン・予約データ取得
ConoHa VPS (現行)
  ↓ Xvfb + 仮想ディスプレイ
Supabase
  ↓ sync_service.py で同期
よやくらくDB
```

**理由**:
- 現行のzendriver + ステルスJSでbot検知テスト4/4通過済み
- 競合がさくらインターネットの固定IPで動いている→VPSでも十分
- まず動かして、問題が出てから高度な対策を追加

### Phase 2: 問題発生時のアップグレード

| 問題 | 対策 |
|------|------|
| CAPTCHAが頻発 | NopeCHA拡張追加 (¥0〜$10/月) |
| IPブロック | IPRoyal レジデンシャルプロキシ ($1.75/GB) |
| CDP検出 | Patchright に移行 (pip install patchright) |
| Akamai Bot Manager検出 | curl_cffi でcookie harvesting |

### Phase 3: 本格運用（10+サロン対応時）

```
Patchright + curl_cffi
  ↓ ハイブリッド: ブラウザでセッション取得、APIリクエストはcurl_cffi
SOAX モバイルプロキシ (docomo回線)
  ↓ サロンごとに固定IP割当
NopeCHA (CAPTCHA自動解決)
  ↓
Supabase + sync_service.py
```

## 7. 法的リスク評価

### 7.1 法的構造

| リスク種別 | 該当法 | リスクレベル | 詳細 |
|-----------|--------|-------------|------|
| **利用規約違反（民事）** | 民法 | **高** | HPB利用規約第5条2項[2]「承認した以外の方法」に該当 |
| **不正アクセス（刑事）** | 不正アクセス禁止法 | **低** | サロン本人の同意があれば第3条但書で適用除外 |
| **業務妨害（刑事）** | 刑法233/234条 | **低** | 低頻度アクセスなら該当しない |

### 7.2 競合の法的状況

- **Recruitは一度も競合を訴えていない**（2017年〜現在）
- SalonConnect: 2,000+サロン、2006年創業で19年間運用
- DOUKI: 個人開発で公開運用中
- **事実上の黙認状態**

### 7.3 リスク軽減策

1. **サロンから明示的な書面同意を取得**（不正アクセス法対策）
2. **アクセス頻度を控えめに**（5分間隔以上、業務妨害対策）
3. **利用規約にサロン自身の責任を明記**（SalonConnect/Salons Solutionと同じ手法）
4. **将来的にRecruit公式パートナーシップを模索**
